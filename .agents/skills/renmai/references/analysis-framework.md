# 分析框架

这一页定义“怎么从指标走到结论”。指标由脚本算，结论由 Agent 写；但结论必须能被指标和消息证据支撑。

## 1. 分析顺序：结构 → 资源 → 关系 → 行动

1. **结构**：层级分布、核心圈构成、集中度、群规模。
2. **资源**：用户标注的 `labels.tier` 覆盖了哪些格子，哪些格子是空的。
3. **关系**：谁在升温、谁在冷却、谁欠回复、谁只是名单。
4. **行动**：本周三条，每条对应一个具体的人和一个具体的动作。

不要反过来：先讲某个人的故事，再找指标佐证。那是叙事，不是分析。

## 2. 四种读数

### 2.1 层级读数

对每一层回答三个问题：

- 这一层有多少人、多少消息？
- 构成是什么（家人 / 同辈 / 资源 / 服务）？
- 这一层最大的风险是什么？

示例：

> 核心圈 10 人、56,884 条。家人 3、同学/伙伴 4、密友 3，资源层只有 1 个。情感底盘很厚，事业杠杆很薄。

### 2.2 象限读数

| | 资源低 | 资源高 |
|---|---|---|
| **关系强** | 陪伴 | 杠杆 |
| **关系弱** | 噪音 | 隐形资产 |

判断时只使用两类输入：

- 关系强度：脚本算的 `strength` / `days_since` / `total`
- 资源量级：用户标注的 `labels.tier`

**禁止**从聊天内容推断财富、职务、家庭关系。

### 2.3 桥接读数

- `bridge_score` 高 = 他能介绍很多“你也聊过”的人。
- `betweenness` 高 = 他在图里像路由器。
- `constraint` 低 = 他站在结构洞上，能连接不同圈子。

结论要落到“用他做什么”，而不是“他很中心”。

### 2.4 关系债读数

- 优先级 = 强度 × 沉默时长（脚本已排序）。
- 只挑 3–5 条写进结论；118 条全列没有意义。
- 每条必须给出“为什么是他”和“说什么”。

## 3. 怎么写结论（thesis）

一条合格的 headline 必须同时满足：

1. 是一个判断，不是描述（“网络在维持，不在扩张”，不是“有很多人”）。
2. 能被至少两个指标支持。
3. 指向一个动作。

summary 用 3–5 句话，覆盖：

- 总规模与热度比例
- 集中度（前几个人占多少）
- 资源层的深度（标注人数 vs 个位数消息人数）
- 最大的结构问题

## 4. 证据规则

每个关键结论附：

```json
{
  "evidence_level": "medium",
  "evidence_message_ids": ["msg_..."],
  "stats_fields": ["person.wxid_x.total", "stats.debt"],
  "quote": "消息中的真实连续片段"
}
```

- `evidence_level`：`high` / `medium` / `low` / `insufficient`
- `evidence_message_ids`：必须来自当前 bundle，格式 `msg_` + 64 位 hex
- `quote`：必须是引用消息正文或转写的**连续片段**
- `stats_fields`：`stats.*` / `person.<username>.*` / `graph.<metric>.<username>`

没有证据时，写 `insufficient`，不要硬编。

## 5. 常见错误

| 错误 | 为什么错 | 改法 |
|---|---|---|
| “这个人很厉害” | 不可验证，且冒犯 | “他是 X 机构负责人，能提供 Y” |
| “消息少 = 关系差” | 线下关系不可见 | 标注“微信盲区”，请用户补充 |
| “群多 = 人脉广” | 群是资源池，不是关系 | 看群内发言占比与桥接分 |
| “他不回我” | 可能只是没看到 | 用“最后一条是对方发的 + 沉默天数” |
| 把 118 条关系债全列出来 | 没有行动价值 | 只挑 3–5 条 |
| 用“价值 / 利用”描述朋友 | 关系不是资产 | 象限只用于资源层，不用于家人密友 |

## 6. 改写示例

**草稿（脚本生成）**

> 甲：消息 900 条，最近 2 天，共同群 6 个，状态：跨群节点。

**改写（Agent）**

> 甲：900 条、70 个会话段，其中 65% 由他发起；他自建的两个群都把你拉了进去，你和乙、丙也各建了一个三人小群把他请进来。上个月他主动问“需要我做点什么”，之后你唯一明确的请求，是让他帮忙确认一笔小额报销。
>
> → 把这周的汇报做成落地清单，不是技术秀。

差别：草稿描述指标，改写描述**位置 + 卡点 + 动作**，并且每个判断都能落回具体消息。

## 7. 写作语气

- 直接、具体、不奉承。
- 不说“你应该多社交”，说“这周发三条具体消息”。
- 不评价用户的人格，只描述行为模式。
- 对高资源关系，用“交付”而不是“维护”。
- 对家人密友，不要用资源语言。
