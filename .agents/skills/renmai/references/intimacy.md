# 亲密关系：人脉图谱里的一层

恋爱不是人脉之外的东西，它是最强的一种“强连接”。所以人脉系统里必须有这一层——但它必须被放在正确的位置。

## 1. 两层结构

```
人脉图（全部关系）
  └─ 亲密关系（候选）        ← 本页
       └─ 单段关系深潜        ← she-love-me 引擎
```

- **第一层**回答：在你的整张网里，哪些关系可能已经越过“朋友/同事”，需要单独对待。
- **第二层**回答：这一段关系现在是什么状态、在往哪走、风险是什么。

不要把人脉指标（消息量、共同群）当成感情结论；也不要用恋爱框架去看所有关系。

## 2. 候选信号（结构，不是判断）

| 信号 | 计算 | 为什么相关 |
|---|---|---|
| 深夜占比 | 23:00–02:00 的消息比例 | 亲密关系更常出现在非工作时段 |
| 强信号词 | 想你 / 喜欢你 / 爱你 / 在一起 / 老公 / 老婆 / 亲亲 / 抱抱 | 语言上的直接线索 |
| 弱信号词 | 晚安 / 早安 / 宝贝 / 亲爱的 / 宝宝 / 约会 | 需要结合语境，误报率高 |
| 最长连续天数 | 连续每天有消息的最长天数 | 日常化程度 |
| 媒体占比 | 表情 / 图片 / 语音 / 视频比例 | 非事务性沟通 |
| 双向均衡 | `1 - |我-对方|/(我+对方)` | 对等投入 |
| 共同群折扣 | 共同群越多，越可能是同事/同学 | 降低误报 |

分数 = 0.28 强度 + 0.20 深夜 + 0.20 关键词 + 0.12 连续 + 0.10 均衡 + 0.10 媒体 − 共同群折扣。

置信度：

- `high`：强信号 ≥5、深夜 ≥15%、共同群 ≤8
- `medium`：强信号 ≥2 或 深夜 ≥20%
- `low`：其余

**这只是“值得看一眼”，不是“他们在谈恋爱”。**

## 3. 必须由用户确认

候选默认全部是 `candidate`。用户可以在 `data/network/intimacy_overrides.json` 里标记：

```json
{
  "wxid_xxx": "confirmed",
  "wxid_yyy": "excluded"
}
```

- `excluded`：不再出现在报告里
- `confirmed`：保留，并可以进入深潜

**Agent 不得替用户确认或否认一段关系。**

## 4. 深潜（调用 she-love-me）

```bash
python scripts/network_deepdive.py --person "某人"
```

会复用 she-love-me 的：

- `stats_analyzer.py` → `stats.json`（回复速度、对称性、情绪词）
- `build_chat_history.py` → `chat_history.txt`（分层采样）
- `generate_html_report.py` → 传入 `--analysis` 后生成完整恋爱分析报告

深潜结果是“这一段关系”的视角；人脉图是“它在整张网里的位置”。两者要一起看：

- 关系很强，但在人脉图里是孤岛 → 这段关系承载了过多社交功能
- 关系很浅，但资源量级很高 → 典型的“名单关系”
- 关系很强，且是桥接者 → 这段关系同时是情感和结构资产

## 5. 写作边界

- 不判断“她爱不爱你”，只描述行为与结构。
- 不把亲密关系当资源；资源语言只用于资源层。
- 不输出聊天原文；引用默认隐藏。
- 不替用户公开、传播或评价对方的私人信息。
